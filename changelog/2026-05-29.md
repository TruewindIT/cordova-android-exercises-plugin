# Changelog - Version 1.2.0 (alt-permissions branch)

This document tracks all the modifications made in this version of the **Cordova Exercises Health Plugin** (`com.axians.requestexercisepermissionsplugin`) on the **alt-permissions** branch. This branch is customized to exclude Heart Rate tracking permissions.

---

## 🚀 Key Changes in this Version

### 1. Android: Dependency & Build Chain Upgrades
*   **Health Connect Client SDK**: Bumped `androidx.health.connect:connect-client` from `1.1.0-alpha07` (alpha) to **`1.1.0` (Stable / Production Ready)** inside `src/android/build.gradle`.
*   **Kotlin Toolchain**: Upgraded `GradlePluginKotlinVersion` preference in `plugin.xml` from **`1.3.50`** (legacy from 2019) to **`1.9.22`** (stable modern standard).

### 2. iOS: Expanded HealthKit Activity Mapping (No Heart Rate Permissions Touched)
*   Added native case coverage in the `nameForWorkoutActivityType` mapping switch inside `RequestExercisePermissionsPlugin.m` to support modern activities introduced in recent iOS releases:
    *   `HKWorkoutActivityTypePickleball` $\rightarrow$ `"Pickleball"`
    *   `HKWorkoutActivityTypeSocialDance` $\rightarrow$ `"Social Dance"` *(successor to the deprecated `.dance` type)*
    *   `HKWorkoutActivityTypeCooldown` $\rightarrow$ `"Cooldown"`
    *   `HKWorkoutActivityTypeSwimBikeRun` $\rightarrow$ `"Swim Bike Run"` *(multisport / triathlons)*
    *   `HKWorkoutActivityTypeUnderwaterDiving` $\rightarrow$ `"Underwater Diving"`
    *   `HKWorkoutActivityTypeDiscSports` $\rightarrow$ `"Disc Sports"`
    *   `HKWorkoutActivityTypeFitnessGaming` $\rightarrow$ `"Fitness Gaming"`
    *   `HKWorkoutActivityTypeCardioDance` $\rightarrow$ `"Cardio Dance"`
*   Restored mapping for `HKWorkoutActivityTypeMixedCardio` to avoid fallback mismatches.
*   **Important**: The `requestPermissions` method's custom, heart-rate-free permission set was preserved intact.

### 3. Documentation (README.md)
*   **Fixed JavaScript Month Bug**: Corrected the JS Date constructor example where `new Date(currentYear, 3, 1)` (which represents April 1st due to 0-indexing) was commented as `Jan 1st`. Changed it to `new Date(currentYear, 0, 1)`.
*   **iOS Architecture Clarified**: Removed outdated documentation references indicating Swift compilation retain cycles. Validated and documented the pure Objective-C GCD serialization queue and `__weak` safety guarantees.
*   **Added JSON Output Specs**: Fully documented the structured array payload schema for both platforms (customized to exclude Heart Rate samples).

## ⚠️ User & Device Impact (Breaking Changes)

### 🔴 Increase of Android `minSdkVersion` to `26` (Android 8.0 Oreo)
> [!CAUTION]
> **CRITICAL BREAKING CHANGE**
>
> The stable Android Health Connect Client SDK (`1.1.0`) strictly requires a minimum SDK version of **`26`**. 
>
> **Impact on Host Applications**:
> *   If the host Cordova or Capacitor application defines a `minSdkVersion` lower than `26` (e.g. Capacitor's default `24`), **the Android Gradle build will fail with a Manifest Merger exception**.
> *   **Resolution**: You must increase the host application's `minSdkVersion` to at least `26` (usually inside `variables.gradle` under `minSdkVersion = 26` for Capacitor, or via `preference` in `config.xml` for Cordova).
>
> **Impact on Users' Devices**:
> *   The app will **no longer install or run on devices older than Android 8.0**. 
> *   *Why this is acceptable*: Google Health Connect is natively integrated starting from Android 14, and legacy support via the Google Play Store is only offered on Android 8.0+. Older devices could not utilize Health Connect anyway.

### 🟢 Zero Breaking Changes for iOS
*   The iOS changes are fully backward-compatible.
*   Activities introduced in newer iOS versions are guarded with standard native `@available(...)` runtime selectors, preventing crashes on older iOS devices.
*   Newer activity enums default gracefully to generic categories if queried on older OS versions.
